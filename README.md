# 실시간 날씨·미세먼지 대시보드 (`26-w10-weather`)

> 이 README는 실습을 완성한 뒤, 배포 직전 단계에서 직접 채워 넣습니다.
> 자세한 실습 절차는 [`guide.md`](./guide.md)를 참고하세요.

## 소개

Open-Meteo의 글로벌 기상 관측소 API와 연동하여 대한민국 주요 도시 및 전 세계 도시의 실시간 기상 상태(기온, 체감 온도, 습도, 풍속, 강수확률)와 환경부 기준 미세먼지(PM10)·초미세먼지(PM2.5) 대기질 상태를 한눈에 파악할 수 있는 반응형 웹 대시보드입니다.

## 어떻게 만들었나요 (Antigravity IDE 경험)

- **도구의 차이**: 이전 주차의 GitHub Copilot은 질문에 대해 바로 코드를 작성해 주는 보조자였다면, Antigravity IDE는 요청을 받자마자 전체 프로젝트를 분석하고 **Implementation Plan(구현 계획서)**을 먼저 작성해 보여주었습니다.
- **Human-in-the-loop**: AI가 어떤 컴포넌트를 분리하고 디바운스와 에러 핸들링을 어떻게 구현할지 설계도를 미리 검토하고 승인(Proceed)하는 과정을 통해 개발 주도권을 유지할 수 있었습니다.
- **Walkthrough 관찰**: 에이전트가 코드를 완성한 뒤 터미널에서 빌드 및 오류 여부를 스스로 검증하는 Walkthrough 과정을 보며 에이전틱 코딩의 높은 신뢰성을 체감했습니다.

## 데이터는 어떻게 가져오나요 (외부 API 아키텍처)

- **Open-Meteo의 특징**: 전 세계 국립 기상청 데이터를 바탕으로 무료 및 무인증(API Key 불필요)으로 제공되는 오픈 기상 데이터 서비스입니다.
- **통신 계층 분리**: `App.jsx` 안에 `fetch` 로직을 직접 넣지 않고 `src/api/weather.js` 모듈로 통신 로직을 완전히 격리하여 코드의 유지보수성과 재사용성을 극대화했습니다.
- **디바운스(Debounce)**: 도시 검색창 입력 시 매 타자마다 API를 호출하면 순식간에 수십 번의 트래픽이 발생하여 DoS 형태의 부하를 유발하거나 429 에러로 차단될 위험이 있으므로, 사용자의 입력이 멈춘 후 400ms 뒤에 한 번만 호출되도록 디바운스를 적용했습니다.

## 보안에서 확인한 것 (사이버보안과 체크포인트)

- **Public API vs Secret API**: Open-Meteo처럼 키가 필요 없는 공개 API는 브라우저(React)에서 직접 호출해도 무방하지만, 결제나 회원 데이터처럼 비밀 키(`secret key`)가 필요한 유료 API를 프론트엔드에서 직접 호출하면 개발자 도구(Network 탭)와 빌드 파일에서 키가 100% 탈취됩니다. 따라서 보안 API는 반드시 백엔드 프록시 서버(BFF)나 Edge Function을 거쳐 서버에서 키를 주입해야 합니다.
- **HTTPS와 Mixed Content 방어**: 브라우저는 보안 연결(HTTPS)로 배포된 웹사이트에서 안전하지 않은 HTTP 엔드포인트를 호출하는 것을 차단합니다(Mixed Content). 본 프로젝트의 모든 API 호출은 안전한 HTTPS 프로토콜로 암호화 통신합니다.
