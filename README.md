# 실시간 날씨·미세먼지 대시보드 (`26-w10-weather`)

전 세계 기상 데이터를 실시간으로 제공하는 공개 기상 API(Open-Meteo)와 React 19를 연동하여 제작한 반응형 스마트 날씨 및 대기질 관측 대시보드입니다.

---

## 소개

이 프로젝트는 브라우저에서 전 세계 도시의 실시간 기상 상태와 대기질을 한눈에 확인할 수 있는 올인원 기상 관측 대시보드입니다.

- **실시간 날씨 관측**: 현재 기온, 체감온도, 습도, 풍속, 강수량 및 날씨 상태(한국어 라벨 & Lucide React 아이콘)
- **환경부 기준 대기질 정보**: PM10(미세먼지), PM2.5(초미세먼지) 수치 및 4단계(좋음, 보통, 나쁨, 매우 나쁨) 컬러 뱃지 및 행동 요령
- **24시간 시간별 기온 차트**: 오늘 하루 시간대별 기온 변화를 직관적으로 파악할 수 있는 가로 스크롤 SVG 미니 꺾은선 차트
- **7일간 주간 일기예보**: 향후 일주일간의 요일별 날씨, 강수 확률(%), 최고/최저 기온 범위 시각화 바
- **전 세계 도시 검색**: 400ms 디바운스(Debounce)가 적용된 실시간 자동완성 검색 및 드롭다운
- **나만의 커스터마이징 기능 탑재**: 날씨 상태 및 주/야간에 따른 동적 비주얼 테마 & `localStorage` 기반 최근 본 도시 즐겨찾기

## 어떻게 만들었나요 (Antigravity IDE 경험)

- **자율형 에이전트와 체계적 계획 수립**:
  - 기존 주차에서 사용했던 단순 자동완성 도구와 달리, Antigravity IDE는 코드를 바로 수정하지 않고 먼저 명확한 **구현 계획(Implementation Plan)**을 세워 사용자 피드백을 받는 프로세스가 매우 인상적이었습니다.
  - 전체 시스템의 구조와 변경 범위를 먼저 확인하고 승인(Proceed)할 수 있어 대규모 리팩토링이나 컴포넌트 분리 작업 시에도 불안감 없이 안정적으로 개발을 진행할 수 있었습니다.
- **점진적 2단계 빌드업과 Walkthrough**:
  - 친숙한 Vite 초기 화면에서 시작하여 1단계(기본 기상/대기질 카드 구축) → 2단계(컴포넌트 모듈화, 24시간 SVG 차트, 7일 예보, 디바운스 검색)로 단계별로 발전해 나가는 워크플로우를 체감했습니다.
  - 작업 완료 후 자체적으로 빌드를 검증하고 변경 내역을 보고서(Walkthrough) 형태로 정리해 주는 점이 뛰어났습니다.
- **Git 커밋 위임**:
  - 프로젝트에 사전 정의된 규칙(`GEMINI.md`)을 에이전트가 인지하여, 커밋 메시지 규칙(한국어 작성, 기술 용어 보존, 불릿 포인트 상세화, Co-authored-by 서명)을 철저히 지킨 고품질 커밋을 자동으로 만들어 주어 생산성이 크게 향상되었습니다.

## 데이터는 어떻게 가져오나요 (외부 API 아키텍처)

- **Open-Meteo 기상 및 대기질 API**:
  - 회원가입이나 비밀 API Key가 필요 없는 공개 API(Public API)로, 비상업적 목적에 한해 하루 최대 10,000건의 기상 관측 및 예보 데이터를 무료로 제공합니다.
  - 날씨 예보(`forecast`), 공기질(`air-quality`), 도시 지오코딩(`geocoding-api`) 엔드포인트를 적재적소에 연동했습니다.
- **UI 컴포넌트와 API 통신 로직의 철저한 분리 (`src/api/weather.js`)**:
  - React 컴포넌트(`App.jsx` 및 자식 컴포넌트)는 오직 UI 렌더링과 사용자 인터랙션에만 집중하고, 네트워크 통신(`fetch`), URL 파라미터 조합, HTTP 에러 핸들링, WMO 코드 변환 로직은 `src/api/weather.js` 모듈로 분리(Decoupling)했습니다.
  - 이를 통해 API 스펙이 변경되더라도 UI 컴포넌트를 수정할 필요 없이 통신 모듈만 유지보수할 수 있는 깔끔한 아키텍처를 구축했습니다.
- **도시 검색 디바운스(Debounce 400ms)의 필요성**:
  - 검색창에 "Seoul"을 입력할 때 한 글자 타이핑마다 즉시 API를 호출하면 불필요한 네트워크 트래픽이 급증하고, API 서버로부터 `429 Too Many Requests`(요청 한도 초과) 에러로 IP가 일시 차단될 위험이 있습니다.
  - 사용자의 입력이 멈춘 후 400ms 동안 추가 입력이 없을 때만 단 1회의 검색 API를 호출하도록 디바운스를 적용하여 불필요한 DoS성 요청을 완벽히 방지했습니다.

## 보안에서 확인한 것 (사이버보안과 체크포인트)

1. **공개 API(Public API) vs 비밀 API(Private/Secret API)의 보안 아키텍처**:
   - Open-Meteo는 API Key가 필요 없는 완전 공개 API이므로 프론트엔드(React)에서 직접 HTTPS 호출이 가능합니다.
   - 하지만 유료 결제 모듈이나 사내 핵심 데이터, OpenAI API처럼 **비밀 키(Secret Key)**가 필요한 API는 **절대로 프론트엔드 코드에 키를 넣어서는 안 됩니다**.
2. **프론트엔드 직접 호출의 위험성과 백엔드 프록시(BFF)의 필요성**:
   - 프론트엔드 자바스크립트에 Secret Key를 하드코딩하거나 환경변수(`VITE_...`)로 넣으면, 브라우저의 개발자 도구(F12) Network 탭과 번들 파일(`dist/*.js`)에서 키가 100% 노출됩니다.
   - 키가 탈취되면 거액의 무단 과금이 청구되거나 데이터 유출 사고가 발생하므로, 반드시 **백엔드 프록시 서버(BFF, Backend For Frontend)**를 중간에 두어 클라이언트는 세션/토큰으로만 프록시와 통신하고, 프록시 서버 내부에서 안전하게 Secret Key를 관리하여 호출해야 합니다.
3. **CORS와 Mixed Content (HTTPS 암호화 통신 방어)**:
   - 프로덕션 배포 사이트가 안전한 `https://` 보안 통신을 사용할 때, 안전하지 않은 `http://` API 엔드포인트를 호출하면 브라우저 보안 정책에 의해 통신이 강제 차단됩니다(Mixed Content 방어).
   - 따라서 중간자 공격(MITM) 및 패킷 감청을 방지하기 위해 모든 외부 API 통신은 반드시 HTTPS 암호화 프로토콜을 사용해야 합니다.

## 커스터마이징한 부분

기본 요구사항 외에 대시보드의 사용성과 시각적 완성도를 높이기 위해 다음과 같은 고급 기능을 구현했습니다:

1. **☀️ 라이트 모드 기본 지원 및 다크 모드 원클릭 토글**:
   - 접속 시 밝고 세련된 **라이트 모드(Light Mode)**를 기본값으로 적용하여 가독성과 산뜻한 느낌을 제공합니다.
   - 상단 헤더에 `Sun`/`Moon` 아이콘의 테마 토글 버튼을 배치하여 언제든 다크 모드로 부드럽게 전환할 수 있으며, `localStorage`를 통해 사용자의 설정을 영구 보존합니다.
2. **🎨 기상 상태 연동 고화질 배경 이미지 및 감성 그라데이션 자동 결합**:
   - 현재 날씨(맑음 낮/밤, 흐림 낮/밤, 비, 눈, 뇌우, 안개 등 8개 분류)와 주/야간(`is_day`) 상태를 자동 판별하여, 어울리는 Unsplash 고화질 기상 사진과 감성적인 색상 그라데이션이 자동으로 배경에 적용됩니다.
   - 가독성을 위해 테마 모드별 반투명 틴트 오버레이와 카드 글래스모피즘(`backdrop-filter: blur(16px)`)을 적용하여 텍스트 대비 명도를 완벽하게 확보했습니다.
3. **⭐ `localStorage` 기반 '최근 본 도시' 즐겨찾기 시스템**:
   - 사용자가 검색하거나 선택한 도시를 로컬 저장소에 최대 5개까지 자동 보관하여 원클릭으로 다시 조회하고, 개별/전체 삭제를 지원합니다.
