# 실시간 날씨·미세먼지 대시보드 (`26-w10-weather`)

> Google Antigravity IDE를 활용하여 제작한 실시간 기상·대기질 모니터링 웹 대시보드입니다.  
> Open-Meteo의 글로벌 기상 및 공기질 오픈 API를 연동하여 전 세계 도시의 날씨와 미세먼지 정보를 직관적으로 시각화합니다.

---

## 🌤️ 소개

본 프로젝트는 최신 React 19와 Vite 환경에서 구축된 반응형 기상 대시보드 애플리케이션입니다.

- **주요 도시 원클릭 조회**: 서울(강서/시청), 인천, 부산, 대구, 대전, 광주, 제주 등 국내 주요 거점 날씨 즉시 확인
- **전 세계 글로벌 도시 검색**: Open-Meteo Geocoding API를 연동하고 400ms 디바운스(Debounce)를 적용한 스마트 자동완성 검색창
- **실시간 날씨 & 미세먼지 카드**: 기온, 체감온도, 상대습도, 풍속, 강수량 및 환경부 기준 4단계(좋음/보통/나쁨/매우나쁨) 공기질 평가 시각화
- **24시간 시간별 기온 추이 차트**: 오늘 하루 기온 변화를 순수 인라인 SVG 꺾은선 차트로 가볍고 유려하게 렌더링 (가로 터치 스크롤 지원)
- **7일간 주간 일기예보**: 요일별 최고/최저 기온 범위 게이지 및 강수 확률(%) 예보
- **동적 비주얼 테마 & 다크모드**: 날씨 상태와 주야간에 따른 감성적인 배경 그라데이션 및 글래스모피즘(Glassmorphism) 카드 디자인

## 🤖 어떻게 만들었나요 (Antigravity IDE 경험)

1. **GitHub Copilot과의 차이점**:
   - 이전 주차에서 사용했던 Copilot이 에디터 내에서 인라인 코드 자동 완성을 주로 담당했다면, **Antigravity IDE**는 프로젝트 전체 구조를 파악하고 기획부터 설계, 모듈 분할, 구현, 검증, Git 커밋까지 전 과정을 자율적으로 주도하는 '완결형 에이전트(Agentic IDE)'였습니다.
2. **구현 계획(Implementation Plan)의 사전 검토**:
   - AI가 무작정 코드를 변경하지 않고, 변경할 컴포넌트 구조, 데이터 흐름, 다이어그램, 검증 계획을 담은 아티팩트를 먼저 작성하여 개발자의 승인(Proceed)을 받는 단계가 매우 인상 깊었습니다. 이를 통해 의도치 않은 코드 파괴를 방지하고 높은 예측 가능성을 확보할 수 있었습니다.
3. **자체 기능 검증(Walkthrough) 관찰**:
   - 작업 완료 후 에이전트가 스스로 `oxlint` 정적 분석과 `vite build` 프로덕션 번들링 테스트를 실행하여 오류 0건을 확인하고, 리포트 아티팩트(`walkthrough.md`)를 남겨 작업 결과의 신뢰도를 즉시 확인할 수 있었습니다.

## 📡 데이터는 어떻게 가져오나요 (외부 API 아키텍처)

1. **Open-Meteo API의 특징**:
   - 비영리 오픈 기상 프로젝트로, 별도의 회원가입이나 Secret API Key 발급 없이 완전 무료로 사용할 수 있는 Public API입니다.
   - WMO(세계기상기구) 표준 기상 코드와 지리 좌표(위도/경도) 기반의 고정밀 기상/대기질/지오코딩 데이터를 제공합니다.
2. **UI와 API 통신 로직의 분리 (`src/api/weather.js`)**:
   - 관심사의 분리(Separation of Concerns) 원칙을 적용하여, UI 컴포넌트(`App.jsx` 및 자식 컴포넌트들)는 오직 화면 렌더링에만 집중하고, 데이터 fetch 및 에러 처리, 단위 변환 등의 로직은 `weather.js` 모듈로 철저히 캡슐화했습니다.
   - 이를 통해 추후 기상 공급자 API가 변경되더라도 UI 코드 수정 없이 API 레이어만 손쉽게 교체할 수 있는 유연성을 확보했습니다.
3. **도시 검색창의 400ms 디바운스(Debounce)**:
   - 사용자가 검색창에 타이핑할 때마다(`S-e-o-u-l`) 매 글자 즉시 API를 호출하면 순식간에 불필요한 요청이 다량 발생합니다.
   - 디바운스를 적용하여 타이핑이 400ms 동안 멈췄을 때 최종 입력값으로만 1회 호출하도록 제어함으로써 클라이언트 네트워크 낭비를 줄이고 서버 측의 `429 Too Many Requests` IP 차단을 원천 방지했습니다.

## 🛡️ 보안에서 확인한 것 (사이버보안과 체크포인트)

1. **완전 공개 Public API vs 비밀 키(Secret Key)가 필요한 보안 API**:
   - Open-Meteo처럼 완전 공개된 API는 브라우저 클라이언트에서 직접 호출해도 무방합니다.
   - 하지만 유료 결제 모듈이나 사내 회원/결제 데이터베이스처럼 비밀 키(`Secret Key`)가 필요한 API는 **절대로 React 같은 프론트엔드 코드에 키를 하드코딩하거나 클라이언트에서 직접 호출해서는 안 됩니다.**
   - 브라우저 개발자 도구(F12)의 Network 탭이나 빌드된 JS 파일에서 누구나 키를 탈취할 수 있어 막대한 금전적 피해와 개인정보 유출 사고가 발생하기 때문입니다.
2. **백엔드 프록시(BFF, Backend For Frontend)의 필수성**:
   - 비밀 키를 보호하기 위해서는 프론트엔드와 외부 API 사이에 안전한 백엔드 프록시 서버를 두어, 서버 측 환경변수(`.env`)에 비밀 키를 숨겨두고 클라이언트의 인가된 요청만 대리 전달하는 아키텍처가 필수적입니다.
3. **HTTPS와 Mixed Content (혼합 콘텐츠) 방어**:
   - HTTPS 보안 프로토콜로 서비스되는 사이트에서 암호화되지 않은 HTTP API 엔드포인트를 호출할 경우, 브라우저는 보안 정책에 따라 해당 요청을 강제로 차단(Mixed Content Block)합니다.
   - 이는 네트워크 패킷 스니핑이나 중간자 공격(MitM)에 의한 데이터 위·변조를 방지하기 위한 핵심 웹 보안 메커니즘입니다. Open-Meteo의 모든 API는 안전한 HTTPS 프로토콜을 준수합니다.

## 🎨 커스터마이징한 부분

1. **라이트 / 다크 모드 토글 (기본값: 라이트 모드)**:
   - 사용자의 초기 접근성을 고려해 기본값을 라이트 모드로 설정하고, 상단 헤더에 Sun/Moon 원클릭 토글 스위치를 배치했습니다.
   - 사용자의 모드 선택은 `localStorage`에 자동 보존되어 브라우저를 다시 방문해도 유지됩니다.
2. **날씨 상태 & 주야간(`is_day`) 연동 동적 배경 그라데이션**:
   - 현재 조회 중인 도시의 WMO 기상 코드와 낮/밤 정보를 분석하여, 맑은 날(선샤인 블루), 맑은 밤(미드나잇 인디고), 흐림(슬레이트 그레이), 비(딥 아쿠아), 눈(윈터 아이스블루) 등 8가지 맞춤형 멀티 레이어 그라데이션이 대시보드 전체에 부드럽게 전환됩니다.
3. **반투명 글래스모피즘(Glassmorphism) 카드 디자인**:
   - 배경의 감성적인 그라데이션이 은은하게 투영되도록 `backdrop-filter: blur(16px)`와 섬세한 반투명 보더를 적용하여 높은 심미성과 텍스트 가독성을 동시에 달성했습니다.
4. **최근 본 도시(`localStorage`) 즐겨찾기 바 (`RecentCities.jsx`)**:
   - 사용자가 검색하거나 선택한 도시를 로컬 스토리지에 최대 5개까지 자동 누적 보존하여, 상단 뱃지 클릭 한 번으로 이전 도시의 기상 정보를 빠르게 재확인할 수 있도록 편의성을 극대화했습니다.
