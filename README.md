# 실시간 날씨·미세먼지 대시보드 (`26-w10-weather`)

> 자세한 실습 절차는 [`guide.md`](./guide.md)를 참고하세요.

## 소개

- Open-Meteo API 기반 실시간 날씨·미세먼지 대시보드
- 주요 8개 도시 빠른 선택 버튼 + 도시 검색(드롭다운 선택)
- 현재 날씨 카드: 기온, 체감온도, 습도, 풍속, lucide-react 날씨 아이콘
- 미세먼지 카드: PM10/PM2.5 수치, 환경부 기준 등급(좋음/보통/나쁨/매우 나쁨) 뱃지
- 24시간 기온 SVG 꺾은선 차트, 7일 주간 예보(최고/최저 기온, 강수확률)
- 모바일에서도 깨지지 않는 반응형 카드 레이아웃

## 어떻게 만들었나요 (Antigravity IDE 경험)

- Copilot은 질문하면 바로 코드를 써주는 방식이었다면, Antigravity는 계획서를 먼저 보여주고 승인받은 뒤 작업 → 검증까지 하는 방식이라 중간에 방향을 확인할 수 있었음
- 프롬프트 1(기본 화면) → 프롬프트 2(컴포넌트 분리, 차트, 예보, 검색) 2단계로 진행
- Implementation Plan에서 수정 파일 범위, App.jsx에 fetch를 직접 넣지 않고 weather.js 함수를 쓰는지 확인 후 승인
- 코드를 받기 전에 설계를 먼저 검토하니, 결과물이 이상할 때 어디서 어긋났는지 추적하기 쉬웠음
- Walkthrough에서 npm run build 통과까지 스스로 확인해줬지만, 계획에 있던 lint는 실제 보고에 빠져 있었음
- 1단계 커밋이 main에 바로 들어가서, guide.md 브랜치 구조(main 원본 유지 / dev / weather)에 맞게 다시 정리함
- 에이전트가 알아서 해줘도 계획과 결과가 맞는지는 사람이 끝까지 확인해야 한다는 걸 느낌

## 데이터는 어떻게 가져오나요 (외부 API 아키텍처)

- Open-Meteo: 각국 기상청 공개 데이터 기반 무료 API, 회원가입·API Key 없이 HTTPS 요청만으로 날씨·대기질·도시 검색 데이터 제공
- 통신 로직은 src/api/weather.js에만 두고, 컴포넌트는 함수만 import해서 사용
- 분리한 이유
  - API 주소나 응답 형식이 바뀌어도 weather.js만 고치면 됨
  - UI 코드와 통신 코드가 섞이지 않아 읽기 쉽고 재사용 가능
  - 나중에 비밀 키가 필요한 API로 바꾸거나 BFF를 거치게 바꿀 때도 호출 지점이 한 곳이라 교체가 쉬움
- 디바운스가 필요했던 이유
  - 검색창에 글자를 칠 때마다 요청하면 "Seoul" 한 단어에 요청이 5번 나감
  - 서버 입장에선 짧은 시간 대량 요청이라 429 Too Many Requests로 차단될 수 있음
  - 타이핑이 멈추고 400ms 뒤에 마지막 입력으로 1번만 요청하도록 처리

## 보안에서 확인한 것 (사이버보안과 체크포인트)

- 개발자 도구 Network 탭에서 Open-Meteo 요청 주소 확인: 위도·경도만 있고 키가 없음
- Public API는 노출될 비밀이 없어서 브라우저에서 직접 호출해도 괜찮음
- Secret Key가 필요한 API는 키를 절대 프론트엔드 코드에 넣으면 안 됨
  - React 코드에 넣으면 빌드된 JS 파일과 Network 탭에 키가 그대로 보임
  - 탈취된 키로 유료 API를 무단 호출해 요금 폭탄, 사내 API라면 데이터 유출로 이어질 수 있음
  - 그래서 브라우저 → 백엔드 프록시(BFF, Edge Function) → 외부 API 구조로, 키는 서버에만 보관하고 브라우저는 백엔드하고만 통신해야 함
- Mixed Content
  - HTTPS 페이지에서 HTTP 주소를 부르면, 그 HTTP 통신은 암호화가 안 돼서 중간에서 내용을 보거나 바꿔치기할 수 있음
  - 그러면 HTTPS로 지켜놓은 페이지 전체의 안전성이 깨지기 때문에 브라우저가 요청을 차단함
  - Open-Meteo는 HTTPS로 호출하기 때문에 배포 사이트에서도 문제없이 동작

## 커스터마이징한 부분

- 옵션 A 동적 배경 테마
  - weather_code와 낮/밤(is_day)으로 맑음/흐림/비/눈/밤 5가지 테마 판별
  - 도시를 바꾸면 배경 그라데이션이 부드럽게 전환되고, 상단에 현재 테마 뱃지 표시
- 옵션 B 최근 본 도시
  - 검색하거나 선택한 도시를 localStorage(weather_recent_cities)에 최신순, 중복 없이 최대 6개 저장
  - 상단 뱃지로 원클릭 재조회, 개별 삭제와 전체 지우기 가능
  - Application 탭에서 값이 평문으로 저장되는 것 확인
  - localStorage는 같은 출처의 스크립트면 누구나 읽을 수 있어서, 도시 이름 정도는 괜찮지만 토큰이나 개인정보는 저장하면 안 됨
