# 실시간 날씨·미세먼지 대시보드 (`26-w10-weather`)

전 세계 기상 데이터를 실시간 제공하는 **Open-Meteo API**와 연동하여, 국내외 주요 도시의 날씨 및 환경부 기준 미세먼지 수치를 직관적으로 시각화한 모던 반응형 기상 대시보드 웹 애플리케이션입니다.

---

## 소개

본 프로젝트는 React 19와 Vite 기반의 고성능 웹 애플리케이션으로, 복잡한 기상 정보를 카드형 UI와 정교한 SVG 차트로 구성하여 누구나 한눈에 날씨 흐름을 파악할 수 있도록 제작되었습니다.

### 🌟 핵심 기능
1. **주요 거점 도시 원클릭 퀵 선택**: 서울(강서, 시청), 인천, 부산, 대구, 대전, 광주, 제주 등 주요 거점 도시 빠른 조회
2. **실시간 현재 날씨 카드**: 현재 기온(°C), 체감 온도, 상대 습도, 풍속(m/s) 및 WMO 코드 기반 한국어 상태 라벨과 `lucide-react` 동적 아이콘 매핑
3. **환경부 기준 미세먼지 카드**: PM10, PM2.5 실시간 농도(μg/m³), 환경부 4단계(좋음, 보통, 나쁨, 매우 나쁨) 컬러 뱃지 및 프로그레스 바
4. **24시간 시간별 기온 추이 차트**: 외부 무거운 라이브러리 없이 가볍고 정교한 순수 SVG 꺾은선 및 그라디언트 영역 차트 구현 (가로 스크롤 대응)
5. **7일간 주간 일기예보**: 향후 일주일간의 요일별 날씨, 강수 확률(%), 최저~최고 기온 비주얼 범위 바
6. **400ms 디바운스 적용 도시 검색창**: Open-Meteo Geocoding API와 연동된 글로벌 도시 검색 및 자동완성 드롭다운

## 어떻게 만들었나요 (Antigravity IDE 경험)

- **Copilot과의 차이점**: 이전 주차에서 경험한 GitHub Copilot이 주로 타이핑 시점의 인라인 코드 자동완성 도구였다면, Antigravity IDE는 전체 프로젝트의 아키텍처 설계부터 상태 흐름 분석, 코드 작성, 그리고 빌드 및 린트 검증까지 주도적으로 수행하는 진정한 **에이전틱(Agentic) AI 개발 환경**이었습니다.
- **구현 계획(Implementation Plan) 중심 개발**: 코드를 무작정 생성하지 않고, 먼저 아키텍처 다이어그램, 상태 변수 정의, 파일별 변경 계획서(`implementation_plan.md`)를 작성해 사용자에게 승인을 받는 과정을 거쳤습니다. 이를 통해 코드 충돌이나 구조적 결함을 개발 초기에 완벽히 방지할 수 있었습니다.
- **자체 기능 검증(Walkthrough)**: 코드 작성 후 `oxlint` 린트 검사와 `vite build` 번들링 무결성을 스스로 실행하고 검증 리포트(`walkthrough.md`)를 도출하는 과정을 관찰하며 실무 수준의 높은 완성도와 신뢰성을 경험했습니다.
- **프로젝트 규칙(Rules) 기반 Git 커밋 위임**: `GEMINI.md`와 `AGENTS.md`의 커밋 규칙을 기반으로, AI가 불릿 포인트 상세 내역과 `Co-authored-by` 서명을 갖춘 고품질 Git 커밋을 일관되게 생성할 수 있었습니다.

## 데이터는 어떻게 가져오나요 (외부 API 아키텍처)

- **Open-Meteo API의 특징**:
  - API Secret Key 발급이나 회원가입이 불필요한 **완전 무료 공개 Public API**입니다.
  - WMO(세계기상기구) 표준 날씨 코드, 기온, 습도, 풍속, 강수량뿐 아니라 시간별(`hourly`) 및 주간(`daily`) 예보, 대기질(`air-quality`) 데이터까지 고속 HTTPS 엔드포인트로 제공합니다.
- **UI 컴포넌트와 API 통신 로직(`src/api/weather.js`) 분리 이유**:
  - **관심사의 분리(Separation of Concerns)**: 프레젠테이션 계층(React 컴포넌트)과 데이터 통신 계층을 분리함으로써, 추후 API 엔드포인트나 파라미터 규격이 바뀌더라도 UI 코드를 건드리지 않고 API 레이어만 수정할 수 있습니다.
  - **테스트 및 유지보수 용이성**: API 호출 실패 시의 예외 처리와 응답 데이터 정규화를 한곳에서 집중 관리할 수 있습니다.
- **도시 검색 디바운스(Debounce, 400ms)의 필요성**:
  - 검색창에 `Seoul`을 타이핑할 때 한 글자 입력마다 API를 즉시 요청하면 불필요한 네트워크 트래픽과 DoS 형태의 부하가 발생합니다.
  - 타이머를 통해 사용자의 연속 입력이 멈춘 후 400ms 뒤에 1회만 요청하도록 **디바운싱**을 적용하여, 클라이언트와 서버 자원을 절약하고 API 서버의 `HTTP 429 Too Many Requests` 차단을 사전에 방지했습니다.

## 보안에서 확인한 것 (사이버보안과 체크포인트)

- **Public API vs Private/Secret API (키 분리와 백엔드의 필요성)**:
  - Open-Meteo처럼 공개된 읽기 전용 데이터는 브라우저(클라이언트)에서 직접 호출해도 무방합니다.
  - 하지만 결제 모듈, 사내 회원 DB, 생성형 AI API처럼 비밀 키(`Secret Key`)가 필요한 보안/유료 API는 **절대로 React 프론트엔드 코드에 넣어서는 안 됩니다.** 브라우저의 Network 탭이나 배포된 자바스크립트 번들에서 키가 100% 노출되어 거액의 과금 피해나 데이터 유출 사고가 발생합니다.
  - 이를 방어하기 위해 반드시 프론트엔드와 외부 API 사이에 **백엔드 프록시 서버(BFF, Backend For Frontend)**를 구축하고, 비밀 키는 서버 측 환경변수(`.env`)에 안전하게 보관하여 서버 대 서버로 통신해야 합니다.
- **CORS와 Mixed Content (HTTPS 암호화 방어)**:
  - 배포된 웹 애플리케이션(`https://`)에서 암호화되지 않은 비보안 프로토콜(`http://`) 엔드포인트를 호출하면, 중간자 공격(MITM) 및 데이터 변조 위험으로 인해 브라우저의 보안 정책에 의해 통신이 강제로 차단(Mixed Content)됩니다.
  - 본 애플리케이션은 Open-Meteo의 모든 엔드포인트에 보안 암호화 프로토콜인 `HTTPS`만을 사용하여 안전하게 통신합니다.

## 커스터마이징한 부분

본 프로젝트에서는 기본 요구사항 외에 사용자 경험(UX)과 시각적 완성도 및 정보의 유용성을 극대화하기 위해 다음 **3가지 커스터마이징 옵션 기능**을 종합 구축했습니다:

1. **옵션 A: 실시간 날씨 & 주야간 동적 비주얼 테마 (`theme-sunny`, `theme-night`, `theme-rainy`, `theme-snowy`, `theme-cloudy`)**
   - 현재 조회된 도시의 날씨 코드와 주야간 플래그(`current.is_day`)를 실시간 분석합니다.
   - 맑은 날(따뜻한 햇살 앰버/스카이블루), 흐린 날(차분한 그레이), 비/눈 오는 날(쿨 블루/슬레이트), 야간(깊은 네이비)에 맞추어 대시보드 전체 배경 그라데이션이 부드럽게(`0.6s ease`) 전환되는 동적 테마를 적용했습니다.
2. **옵션 B: 최근 조회한 도시 로컬 영구 저장 (`localStorage`) 및 원클릭 재조회**
   - 검색창이나 프리셋을 통해 조회한 도시를 브라우저 `localStorage`에 최대 5개까지 중복 없이 자동 보관합니다.
   - 상단에 '최근 본 도시' 칩 목록을 제공하여 이전에 확인한 도시로 원클릭 즉시 이동할 수 있으며, '비우기' 버튼으로 기록을 간편하게 정리할 수 있습니다.
3. **옵션 C: 상세 기상 지표 확장 (자외선 지수, 일출/일몰 시각, 최고 강수 확률)**
   - Open-Meteo 일별 예보(`daily`) API 파라미터(`sunrise,sunset,uv_index_max,precipitation_probability_max`)를 추가 연동했습니다.
   - 현재 날씨 카드를 **6대 핵심 기상 지표(체감온도, 습도, 풍속, 강수확률, UV 지수, 일출/일몰)** 그리드로 확장하여, 기상청/WMO 기준 자외선 등급 뱃지(낮음/보통/높음/매우높음/위험)와 한국어 일출/일몰 시각을 직관적으로 제공합니다.
