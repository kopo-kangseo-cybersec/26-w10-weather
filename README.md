# 실시간 날씨·미세먼지 대시보드 (`26-w10-weather`)

> Google Antigravity IDE를 활용하여 구축한 차세대 실시간 날씨 및 대기질 분석 기상 대시보드입니다.  
> 전 세계 공개 기상 API(Open-Meteo)를 React 19와 연동하여 기온, 미세먼지, 24시간 기온 추이, 7일간 예보 및 동적 테마를 제공합니다.

---

## 🌟 소개

- **국내 주요 8개 도시 빠른 선택**: 서울(강서), 서울(시청), 인천, 부산, 대구, 대전, 광주, 제주 프리셋 원클릭 조회
- **실시간 날씨 정보**: 현재 기온, 체감 온도, 상대 습도, 풍속, 시간당 강수량 및 WMO 코드 기반 한국어 날씨 라벨과 `lucide-react` 동적 아이콘
- **환경부 기준 미세먼지 카드**: PM10(미세먼지), PM2.5(초미세먼지) 수치(㎍/㎥)와 한국 환경부 4단계(좋음/보통/나쁨/매우나쁨) 등급 배지 및 범례
- **24시간 시간별 기온 SVG 차트**: `weather.hourly` 데이터를 기반으로 한 미니 꺾은선 차트, 그라데이션 영역 채우기, 호버 인터랙션 및 가로 스크롤 시간대별 뷰
- **향후 7일간 주간 기상 예보**: `weather.daily` 데이터를 활용한 요일별 최고/최저 기온 막대 게이지(Range Bar)와 강수 확률(%) 표시
- **사이버보안 디바운스 도시 검색**: `searchCities` Geocoding API와 400ms 디바운스(Debounce)를 결합한 전 세계 도시 실시간 검색

  단순한 한 줄 코드 완성을 지원하던 이전 주차의 GitHub Copilot과 달리, **Antigravity IDE**는 복잡한 요구사항을 입력받았을 때 무작정 코드를 작성하지 않고 전체 아키텍처와 컴포넌트 계층, 예외 처리 방안을 체계적으로 담은 **구현 계획(Implementation Plan)**을 아티팩트로 먼저 제시하고 사용자의 승인(Proceed)을 거친 뒤 실행하는 점이 매우 혁신적이었습니다.
- **점진적 2단계 빌드업과 안전한 롤백**:  
  Vite 기본 화면에서 출발하여 `[1단계: 기본 화면] → [2단계: 대시보드 완성형 고도화]`로 기능을 안전하게 확장해 나갈 수 있었으며, 단계마다 프로젝트 커밋 규칙(`GEMINI.md`)을 준수하여 명확한 불릿 포인트와 Co-authored-by 서명을 갖춘 세이브포인트 커밋을 남겨 언제든 안전하게 복구할 수 있었습니다.
- **자율 디버깅 및 개발 서버 호환성 해결**:  
  Windows 환경에서 IPv6 localhost 바인딩 거부 문제가 발생했을 때, 에이전트가 `netstat`과 `curl`을 통해 스스로 포트 상태를 진단하고 `vite.config.js`에 `server.host: true`를 주입하여 `0.0.0.0` 바인딩으로 해결해내는 뛰어난 자율 디버깅 역량을 체감했습니다.

## 📡 데이터는 어떻게 가져오나요 (외부 API 아키텍처)

- **Open-Meteo API의 특징**:  
  별도의 회원가입이나 Secret API Key 없이도 전 세계 실시간 기상 예보, 공기질(Air Quality), 지오코딩(Geocoding) 데이터를 완전 무료로 제공하는 비영리 오픈 프로젝트 API입니다.
- **아키텍처 분리 (Decoupling)**:  
  UI 렌더링을 담당하는 컴포넌트(`src/App.jsx`, `src/components/*`)와 데이터 통신 및 가공 로직(`src/api/weather.js`)을 철저히 분리했습니다. 이를 통해 비즈니스 로직과 뷰의 결합도를 낮추고, 추후 API 규격이 바뀌거나 캐싱 정책을 추가할 때 UI 코드 수정 없이 통신 레이어만 단독으로 유지보수할 수 있습니다.
- **디바운스(Debounce, 400ms)의 필요성**:  
  사용자가 도시 검색창에 'Seoul'을 입력할 때 매 글자(`S`, `e`, `o`, `u`, `l`)마다 즉시 API를 호출하면 단 1초 만에 불필요한 요청이 다수 발생합니다. 이는 서버에 비정상적인 DoS 공격 형태의 부하를 초래하며, API 서버로부터 `429 Too Many Requests`로 클라이언트 IP가 차단될 위험이 있습니다. 400ms 디바운스를 적용하여 사용자의 입력이 멈춘 시점에 단 1회의 안전한 요청만 발생하도록 최적화했습니다.

## 🛡️ 보안에서 확인한 것 (사이버보안과 체크포인트)

1. **Public API vs Private / Secret API**:  
   Open-Meteo는 공개 데이터이므로 프론트엔드에서 직접 호출해도 무방하지만, 결제 API, 회원 인증, 사내 데이터베이스 연동과 같이 **비밀 키(Secret Key)**가 필요한 유료/보안 API는 브라우저(React)에서 절대 직접 호출해서는 안 됩니다.
2. **클라이언트 직접 호출의 치명적 위험과 백엔드 프록시(BFF)의 필수성**:  
   브라우저의 F12 개발자 도구(Network 탭, 소스 코드 탭)나 번들링된 자바스크립트 파일은 100% 리버스 엔지니어링이 가능하므로 프론트엔드에 하드코딩된 Secret Key는 즉시 탈취됩니다. 이로 인해 거액의 API 과금이나 데이터베이스 탈취 사고가 발생하므로, 반드시 비밀 키를 서버 환경변수에 숨겨두고 호출을 중계하는 **백엔드 프록시 서버(BFF, Backend For Frontend)**를 구축해야 합니다.
3. **HTTPS와 Mixed Content (혼합 콘텐츠 방어)**:  
   배포 사이트가 안전한 `https://` 보안 통신을 사용할 때, API 호출을 평문인 `http://`로 요청하면 중간자 공격(MITM)을 통한 패킷 도청 및 데이터 변조 위협이 존재하므로 웹 브라우저가 통신을 강제로 차단(Mixed Content Block)합니다. 본 프로젝트는 모든 Open-Meteo 엔드포인트를 HTTPS로 호출하여 전송 구간 암호화를 철저히 준수했습니다.

## 🎨 커스터마이징한 부분

### 1. 옵션 A: 날씨 및 낮·밤(`is_day`) 연동 8종 동적 비주얼 테마
- 선택된 도시의 현지 낮/밤(`current.is_day`)과 WMO 날씨 코드를 실시간 분석하여 대시보드 전체 배경에 은은한 기상 무드 그라데이션을 적용했습니다:
  - ☀️ **맑은 낮 (`theme-clear-day`)**: 따스한 햇살 앰버 & 맑은 스카이 블루
  - 🌙 **맑은 밤 (`theme-clear-night`)**: 깊고 고요한 밤하늘 딥 네이비 & 인디고 달빛
  - ☁️ **흐림 (`theme-cloudy` / `theme-cloudy-night`)**: 차분한 슬레이트 그레이 & 차콜
  - 🌧️ **비 (`theme-rain` / `theme-rain-night`)**: 청량한 빗방울 스카이 블루 & 딥 오션
  - ❄️ **눈 (`theme-snow` / `theme-snow-night`)**: 포근한 파스텔 아이스 블루 & 라벤더
- 밤 테마 전환 시 텍스트와 카드 배경이 자동으로 어두운 글래스모피즘 톤으로 전환되어 어떤 날씨에서도 최상의 시각적 가독성을 보장합니다.

### 2. 옵션 B: 최근 본 도시 저장 (`localStorage`)
- 사용자가 검색하거나 선택한 도시를 브라우저 `localStorage`에 최근 5개까지 자동 저장하여 상단에 칩(Pill) 형태로 렌더링했습니다.
- 원클릭으로 최근 조회 도시를 재방문할 수 있으며, 개별 삭제(X) 및 중복 방지 로직을 완비했습니다.
